実験自動化を、Unit / Batch / Loop / Stream で分ける

2026年6月 元リポジトリ: biology_resarch

これは公開製品資料やベンダー情報、レビュー論文を読んで整理したメモです。他社の研究成果を当社の実績として掲載するものではありません。

自動化の話は、いきなり「無人ラボ」から始まると話が飛ぶ。現場では、ピペット1本の精度から、24時間稼働の基盤まで層がある。自分たちの調査では、よく使う切り口として次の4つに分けた。

4つの型

型 何をしているか ざっくりした限界
Unit 単一操作の自動化（分注、希釈など） 精度は高いが、仕事の範囲が狭い
Batch 決まった手順をまとめて回す（HTS など） 変更のたびに組み直しが必要になりやすい
Loop 結果を見て次の実験を決め、また回す AI とロボットの接続、監督の設計が要る
Stream 任意の実験を無人で連続実行する基盤 初期投資が大きく、まだ黎明期

いまの読み方

Unit と Batch は、すでに多くのラボで当たり前になっている。Loop は、ベイズ最適化や能動学習とロボット API を繋いだ事例が増え、実証から実用へ移りつつある、というのが公開情報を読んだときの印象だ。

Stream は Emerald Cloud Lab や Strateos のような「ラボをサービスとして借りる」形が先行している。一方で、初期コストとプロトコル変更の硬さは、いまでも大きい。

カハールの置き場所

当社は Stream を一社で抱え込もうとはしていない。自社ラボでは Loop を回す。手順の裏取り（手順 RAG）、実行の土台（Experiment OS）、空間操作（BioSpatial OS）はその部品だ。

「全部無人」より先に、「計算と実験が同じ日のうちに繋がるか」を見ている。
